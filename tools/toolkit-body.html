T7 · Project starter structure

What is actually required: README.md, a dependency file, and .gitignore. Everything else depends on the project.

project-name/
├── src/
├── tests/
├── docs/
├── README.md
├── .gitignore
├── .env.example
└── requirements.txt        (or package.json)

T8 · README template

The test: download your own project into an empty folder and set it up using only the README. If that works, it is done.

# Project Name

One sentence on what this does.

## What it does
Two or three sentences. What problem it solves,
or what it was built for.

## Requirements
- Python 3.11 (or Node 20, etc.)
- Anything else that must be installed first

## Setup
1. Clone or download this repository
2. Install dependencies:
   pip install -r requirements.txt
3. Copy .env.example to .env and fill in your values
4. Run it:
   python main.py

## Notes
Anything a person would trip over.

## Built with
List the main tools or frameworks.

Checklists

Five recurring routines plus the reset. These five only — checklist overload is how systems die.

CL1 · Start of term

Files

[ ]Create this term's folder in Studies/Courses/
[ ]Add a folder per subject
[ ]Create this term's folder in Development/school/

Calendar

[ ]Add each class as a repeating event for the whole term
[ ]Put room, professor, meeting link, and LMS link in each event
[ ]Add known exam and submission dates
[ ]Set notifications

Accounts

[ ]Confirm LMS access for every subject
[ ]Bookmark each subject's LMS page

Notes

[ ]Add this term's subjects to your notes tool

CL2 · New project

Setup

[ ]Give it a clear name — lowercase, dashes, no spaces
[ ]Decide where it belongs in Development/
[ ]Create the folder
[ ]Open the folder in your editor, not a file
[ ]Initialize Git
[ ]Add a .gitignore before your first commit
[ ]Create README.md
[ ]Create the dependency file
[ ]If it uses keys, create .env and .env.example

CL3 · Before pushing to GitHub

Check

[ ]No keys or passwords anywhere in the code
[ ].env is listed in .gitignore
[ ]node_modules/ or equivalent is ignored
[ ]README explains what it is and how to run it
[ ]Commit messages describe what changed
[ ]It runs from a fresh copy

CL4 · Project finish

Wrap up

[ ]Delete leftover test files
[ ]Update the README to match what it actually does now
[ ]Take screenshots for your portfolio
[ ]Commit and push everything
[ ]Add the deployment link to the README, if there is one
[ ]Write two lines on what you learned
[ ]Move it to personal/ if worth showing, or archive/ if done

CL5 · Security basics

Once

[ ]Set up a password manager
[ ]Change your email password first
[ ]Turn on two-factor auth: email, GitHub, school portal
[ ]Save recovery codes somewhere offline
[ ]Create a personal professional email
[ ]Set it as recovery on GitHub and LinkedIn

Ongoing

[ ]Studies, Upskilling, Career syncing to cloud storage
[ ]Development NOT syncing to cloud storage
[ ]Code pushed to GitHub

CL6 · The 20-minute reset

Files

[ ]Empty or file everything in Downloads
[ ]Clear the Desktop
[ ]File loose documents into the right term and subject

School

[ ]Check your LMS for anything new
[ ]Add new deadlines to your calendar
[ ]Look at the week ahead

Development

[ ]Commit and push work in progress
[ ]Delete leftover test files
[ ]Move finished projects to archive/

Upskilling

[ ]File anything new you saved
[ ]Delete what you won't realistically use

Backups

[ ]Confirm cloud sync is running
[ ]Check nothing important exists only on your laptop

Glossary

The twelve words, one sentence each. The link jumps to the section that teaches it.

FolderA location on your computer where files sit. Nothing special about it.03
ProjectA folder containing everything needed to run what's inside it: the code, a README, and a list of what must be installed.03
WorkspaceWhat your editor shows when you open a whole project folder rather than a single file: the file tree, a terminal, and search across everything.07
Repository (repo)A project that Git is tracking. It holds the files and their history.03
RemoteA copy of your repository stored online, usually on GitHub.03
GitThe tool on your computer that records the history of your project as you work.03
GitHubA website that stores Git repositories online so others can see them and work with you.03
CommitOne saved snapshot in your project's history, with a short description of what changed.03
CloneDownloading a copy of a repository from GitHub to your computer.09
PushUploading your commits from your computer to GitHub.03
TerminalThe text window where you type commands instead of clicking. Built into VS Code.07
DependencySomething your project needs installed in order to run. Listed in requirements.txt or package.json.03

VS Code extensions

You don't need twenty-five.

  • The language extension for what you're learning
  • Prettier, for formatting
  • GitLens, for a clearer view of your project's history

Everything else: add it when you hit a problem it solves. Extensions slow the editor down, and most of them you'll never open.
