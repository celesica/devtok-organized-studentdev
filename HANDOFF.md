## How the build works
`node toolkit.js && node build.js` (run from `tools/`).
- `tools/build.js` renders the guide `.dc.html` export + owner overrides. Sections **00–01** patch the export in place; sections **02–08** are wholesale `SECTION_0N_BODY` constants from `sectionBody(label)`. It also renders the **Toolkit body** (prompts cards, template accordions with `ftree`, checklist accordions) and writes `site/index.html` + `site/css/app.css`.
- `tools/toolkit.js` **parses `planning/toolkit.md`** (the toolkit's source of truth) into `toolkit-prompts.json` (id→{t,uw,b}, for the modal) and `toolkit-cards.json` (groups + featured), and lifts the prompt-modal shell from the export into `toolkit-modal.html`.
- `tools/toolkit-data.js` — hand-structured `TEMPLATES` (ftree node arrays / code blocks) and `CHECKLISTS` (grouped items). Edit this to change templates/checklists; edit `planning/toolkit.md` to change prompts.

Reusable helpers in `build.js`: `ftree()` (interactive folder tree), `vdemo()` (video preview → modal), the clickable-catalogue pattern (`s06Dbs`/`s07Ext`), the chip-filter pattern (`s07Install`), the `.idethumb` enlarge preview (real screenshots), `nbHyphenate()` (ASCII hyphen → U+2011, so grepping built HTML for hyphenated words can miss).

Runtime `site/js/components.js` (hand-written): `[data-act]` — `set`, `toggle`, `tck` (persistent checkbox, localStorage `sdev.reset.v1`), `ckreset` (clears the checkboxes in the enclosing `[data-ckwrap]` only), `openp`/`closep` (prompt modal), `openv`/`openimg` (enlarge modal), `jump`, `copy`, `texp`/`tcol`. Checklist counts (`[data-ck-count]`) are scoped to the nearest `[data-ckwrap]`. `INITIAL` seeds `set`-group defaults (…`c60`, `c70`, `c71`).

## Toolkit shape (for reference)
- **Tab order:** 00 Start … 08 Reset, **Toolkit** — Toolkit is lilac by default, ember when active, no divider before it. Nav inside the toolkit: Prompts · Templates · Checklists.
- **Prompts:** 28, card + fixed-size modal (only `.mpre` scrolls, opens at top). Six featured cards carry an ember-glow SVG star; note points to it.
- **Templates:** accordion. Trees are interactive `ftree` with a Copy that copies the plain-text tree (generated by `tkTreeText`). README/`.gitignore` are code blocks with per-block Copy-code.
- **Checklists:** accordion of persistent checkboxes; each has its own Reset all + count. Multi-group = masonry columns (`.rgroups`), single-group = full width (`.rgroups--full`). Ids namespaced `k<n>_<g>_<i>` so lists never share state (with each other or the section-08 reset).
